Веб-приложение для обработки приказов о назначении стипендий, ведения реестра студентов и выплат, подготовки платёжных файлов для банков и контроля истории операций. Интерфейс реализован на Flutter Web, серверная часть предоставляет REST API на Node.js/Express, а данные хранятся в MongoDB.

## Описание приложения

«Реестр стипендий» помогает автоматизировать обработку приказов о стипендиях и подготовку данных для последующей выплаты. Приложение извлекает сведения из PDF-документов, позволяет проверить и отредактировать распознанные данные, сопоставляет записи со студентами, сохраняет приказы и историю начислений, а затем формирует файлы экспорта.

Система рассчитана на работу через браузер. Для доступа к данным пользователь проходит авторизацию. Сервер проверяет права на защищённых API-маршрутах, а документы приказов могут храниться на сервере и скачиваться через авторизованный API.

## Основное назначение и возможности

Основные задачи приложения:

- **Обработка приказов.** Загрузка PDF, извлечение строк с данными о студентах и суммах, объединение повторяющихся записей одного студента и проверка результатов перед завершением обработки.
- **Ведение реестра студентов.** Хранение ФИО, банка, банковского отделения и лицевого счёта; сопоставление студентов с записями из приказов.
- **Учёт начислений и истории выплат.** Связь начислений с конкретным студентом и приказом, просмотр истории операций и жизненного цикла записи студента.
- **Формирование платёжных файлов.** Генерация XML в формате для импорта в 1С/«СчетаПК» с кодировкой Windows-1251, а также экспорт реестров в XLSX.
- **Работа с документами.** Архивирование исходных PDF и сформированных XML/XLSX/DOCX-файлов, привязка файлов к приказам и скачивание через API.
- **Контроль корректности приказов.** Предварительная проверка данных (Smart Check), проверка наличия архивного исходного PDF и блокировка завершения при критических ошибках.
- **Аналитика.** Сводные показатели по суммам выплат, количеству приказов и получателей, распределению по банкам и сравнению периодов.
- **Аудит и контроль активности.** Запись значимых действий, просмотр журнала аудита и отображение присутствия пользователей в реальном времени.
- **Настройки и авторизация.** Вход по JWT; поддержка LDAP/Active Directory, групп доступа и защищённых настроек подключения.
- **Работа с интерфейсом.** Панель показателей, разделы студентов и приказов, центр документов, импорт, настройки, уведомления, профиль и переключение светлой/тёмной темы.

## Архитектура приложения

Проект разделён на три основные части: `frontend`, `backend` и инфраструктурные конфигурации.

### Frontend

**Каталог:** `frontend/`

Клиентская часть - одностраничное веб-приложение на Flutter. Оно отвечает за интерфейс пользователя, выбор PDF-файлов, отображение и редактирование данных приказа, вызовы API и формирование файлов экспорта.

Основные части:

- `lib/main.dart` - точка входа, локализация, восстановление сессии и настройка темы.
- `lib/screens/` - экраны входа, панели управления, студентов, приказов, импорта, центра документов, аудита, аналитики, настроек и других разделов.
- `lib/models/` - модели данных, используемые интерфейсом.
- `lib/services/api_service.dart` - HTTP-клиент для взаимодействия с backend.
- Остальные сервисы `lib/services/` - разбор PDF, генерация XML и XLSX, экспорт документов, работа с шаблонами и загрузками.
- `lib/widgets/` - переиспользуемые элементы интерфейса.
- `lib/theme/` - оформление и цветовые темы.
- `assets/` - логотипы банков и шрифты.
- `test/` - тесты отдельных сервисов, в том числе парсера PDF.

Frontend хранит JWT в `sessionStorage` текущей вкладки браузера и добавляет его в заголовок `Authorization: Bearer ...` при вызове защищённых API. Базовый URL API задаётся при сборке через `API_BASE_URL`; в production предполагается обращение к `/api` через Nginx.

### Backend

**Каталог:** `backend/`

Backend реализован на Node.js и Express. Он предоставляет REST API, выполняет серверную бизнес-логику, обеспечивает доступ к данным MongoDB, проверяет авторизацию, сохраняет документы и фиксирует аудит.

Основные компоненты:

- `src/server.js` - создание Express-приложения, подключение маршрутов, обработка ошибок, запуск HTTP-сервера и канала присутствия пользователей.
- `src/config/db.js` - подключение к MongoDB с повторными попытками при ошибке соединения.
- `src/routes/` - API-маршруты для авторизации, студентов, приказов, начислений, сертификатов, аналитики, аудита, настроек и LDAP-пользователей.
- `src/models/` - Mongoose-модели пользователей/настроек авторизации, студентов, приказов, документов, начислений, истории студентов, снимков приказов и аудита.
- `src/middleware/` - middleware проверки JWT и дополнительной защиты настроек.
- `src/services/` - логика LDAP, хранения документов, аудита, проверки приказов, снимков состояния, истории студентов и генерации DOCX.
- `src/scripts-*.js` - служебные сценарии для настройки LDAP, генерации хеша пароля и миграционного заполнения дат создания приказов.

Важные принципы работы:

- API проверки состояния доступен по `GET /api/health`; вход выполняется через `/api/auth/login`.
- Защищённые маршруты требуют действительный Bearer JWT.
- Для LDAP могут проверяться членство пользователя в разрешённых группах.
- Документы сохраняются в файловой системе сервера, а их метаданные - в MongoDB.
- Завершение приказа повторно проверяется на сервере; критические ошибки не должны обходиться прямым вызовом API.
- Снимки приказов и записи истории позволяют сохранять состояние и хронологию значимых изменений.

### База данных

Используется **MongoDB**, доступ к которой организован через **Mongoose**.

Ключевые сущности:

| Сущность         | Назначение                                                       |
| ---------------- | ---------------------------------------------------------------- |
| `Student`        | ФИО, банковские реквизиты и ключ сопоставления студента          |
| `Order`          | Номер и дата приказа, статус, строки начислений и итоговые суммы |
| `StudentReward`  | Начисление конкретному студенту в рамках приказа                 |
| `OrderDocument`  | Метаданные исходных и сформированных документов                  |
| `OrderSnapshot`  | Снимки состояния приказа                                         |
| `StudentHistory` | История изменений и событий по студенту                          |
| `AuditLog`       | Журнал значимых действий                                         |
| `AuthSettings`   | Настройки авторизации и LDAP                                     |
| `UserPresence`   | Сведения, используемые для отображения активности пользователей  |

### Infrastructure

В проекте присутствуют Dockerfile для разработки и production-сборки backend и frontend, а также конфигурация Nginx:

- `backend/Dockerfile.dev` и `backend/Dockerfile.prod` - окружение Node.js для разработки и production.
- `frontend/Dockerfile.dev` - запуск Flutter Web в режиме разработки.
- `frontend/Dockerfile.prod` - сборка Flutter Web и публикация статических файлов через Nginx.
- `frontend/nginx.conf` - раздача frontend, SPA fallback и проксирование `/api/` на backend; также настроен WebSocket Upgrade для канала присутствия.

Для production-среды предполагается следующая схема:

1. Браузер загружает Flutter Web из Nginx.
2. Nginx проксирует запросы `/api/` в Node.js backend.
3. Backend обращается к MongoDB.
4. Backend сохраняет документы в подключённом постоянном каталоге.
5. WebSocket-соединение используется для обновления сведений о присутствии пользователей.
