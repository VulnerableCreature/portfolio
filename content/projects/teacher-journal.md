Веб-приложение для ведения учебного журнала преподавателя СПО. Оно объединяет сведения об учебных группах, студентах и дисциплинах с расписанием занятий, темами, оценками и посещаемостью. Приложение предоставляет сводную информацию, инструменты контроля качества данных и выгрузку отчётов.

Frontend реализован на Flutter Web, backend - на Node.js и Express, основное хранилище - PostgreSQL. Сервисы запускаются совместно через Docker Compose.

## Назначение приложения

Основная задача - упростить повседневную работу преподавателя: хранить учебные данные в одном месте, фиксировать результаты занятий и получать сводную информацию без ручного сведения нескольких таблиц.

Приложение поддерживает работу с расписанием **по конкретным календарным датам**. Постоянное повторяющееся недельное расписание занятий не используется. Расписание звонков при этом настраивается по дням недели.

## Основные возможности

- **Обзор:** сводные показатели по группам, студентам, дисциплинам и занятиям, динамика занятий и ближайшие позиции расписания.
- **Журнал занятий:** выбор группы и дисциплины, создание и редактирование занятия, указание темы и типа занятия, внесение оценок и отметок посещаемости.
- **Посещаемость:** статусы присутствия, отсутствия, болезни, опоздания и уважительного отсутствия; массовое заполнение отметок для занятия.
- **Студенты:** список и поиск, профиль студента, принадлежность к группе, статус активности, история занятий и сводные учебные показатели.
- **Учебные группы:** создание, редактирование и удаление групп, просмотр количества активных студентов.
- **Дисциплины:** ведение списка дисциплин и плановых часов лекций и практических занятий, связь дисциплин с группами.
- **Темы занятий:** название темы, дисциплина, группа, тип занятия, плановая дата, заметки и статус выполнения.
- **Расписание:** планирование занятий на выбранные даты с указанием группы, дисциплины, номера пары и аудитории; предусмотрено копирование расписания с обработкой конфликтов.
- **Расписание звонков:** время начала и окончания пар по дням недели, пресеты расписания звонков.
- **Семестры:** настройка дат начала и окончания семестров учебного года.
- **Аналитика:** показатели успеваемости и посещаемости, средние оценки и динамика количества занятий.
- **Поиск:** поиск по студентам, группам, дисциплинам и темам.
- **Контроль качества данных:** поиск занятий без темы, незаполненной посещаемости, конфликтов аудиторий и тем без привязки к группе.
- **Отчёты и экспорт:** выгрузка журнала за период в CSV, а также формирование файлов XLSX/PDF на стороне интерфейса.
- **Аудит:** просмотр журнала зарегистрированных изменений и действий, предусмотренных серверной частью.
- **Пользователи и роли:** вход в систему, управление пользовательскими учётными записями и разграничение доступа для ролей `admin` и `teacher`.

## Архитектура и составляющие

### Frontend

Каталог: `frontend/`

Клиентское приложение построено на Flutter и собирается для запуска в браузере (Flutter Web). Интерфейс содержит навигационную оболочку и экраны работы с журналом, расписанием и справочниками.

Основные части:

- `lib/main.dart` - точка входа приложения.
- `lib/screens/app_shell.dart` - основная оболочка, навигация и основные рабочие сценарии.
- `lib/screens/dashboard_page.dart` - экран обзора.
- `lib/screens/groups_page.dart` - экран учебных групп.
- `lib/screens/settings_page.dart` - настройки учебных периодов.
- `lib/screens/admin_users_page.dart` - управление пользователями.
- `lib/screens/tools_pages.dart` - инструменты контроля качества данных и другие вспомогательные экраны.
- `lib/auth/` - модели, состояние и сервисы авторизации.
- `lib/core/api.dart` - HTTP-клиент для обращения к REST API, передача токена доступа, обновление сессии и обработка сетевых запросов.
- `lib/core/theme.dart` - оформление интерфейса.
- `lib/core/semesters.dart` - работа с настройками семестров.

Клиент использует REST API backend-сервиса для чтения и изменения данных. Адрес API задаётся параметром сборки `API_BASE_URL`; для Docker-сборки используется относительный путь `/api`.

Используемые пакеты и библиотеки включают:

- `flutter` - UI и приложение;
- `dio` - HTTP-запросы;
- `flutter_bloc` - инструмент управления состоянием;
- `fl_chart` - графики;
- `excel` - формирование Excel-файлов;
- `pdf` и `printing` - создание и обработка PDF;
- `intl` - форматирование дат и чисел;
- `talker`, `talker_flutter`, `talker_dio_logger` - журналирование и диагностика.

### Backend

Каталог: `backend/`

Backend - REST API на Node.js с использованием Express. Он выполняет бизнес-операции, валидирует входные данные, взаимодействует с PostgreSQL и контролирует доступ к защищённым маршрутам.

Основные компоненты:

- `src/server.js` - создание Express-приложения, подключение middleware, регистрация маршрутов API и обработка ошибок.
- `src/db.js` - подключение к PostgreSQL и выполнение запросов через пул соединений.
- `src/schema.js` - инициализация схемы базы данных, перенос исходных демонстрационных данных при необходимости и создание начальной учётной записи администратора.
- `src/auth/` - сервисы и маршруты авторизации, проверка доступа, управление пользователями и refresh-токенами.
- `db/schema.sql` - структура таблиц и индексов PostgreSQL.
- `db/legacy-seed.json` - исходные данные для первоначального заполнения пустой базы.

В серверной части используются:

- **Express** - HTTP-сервер и маршрутизация;
- **pg** - работа с PostgreSQL;
- **Zod** - проверка и валидация входных данных;
- **jsonwebtoken** - JWT-токены;
- **bcryptjs** - хеширование паролей;
- **cookie-parser** - обработка cookies;
- **cors** - настройка междоменных запросов;
- **helmet** - HTTP-заголовки безопасности.

Авторизация предусматривает короткоживущий access-токен и refresh-токен. Защищённые маршруты `/api` требуют действительной авторизации; отдельные операции ограничиваются ролью администратора. Параметры секретов и начальной учётной записи задаются через переменные окружения.

Основные группы API:

- `/api/auth` - вход, обновление сессии, выход и управление пользователями;
- `/api/dashboard`, `/api/analytics` - сводные показатели и аналитика;
- `/api/groups`, `/api/students`, `/api/disciplines` - справочники;
- `/api/schedule`, `/api/bells` - расписание занятий и звонков;
- `/api/topics` - темы занятий;
- `/api/journal` - занятия, оценки и посещаемость;
- `/api/search` - глобальный поиск;
- `/api/quality` - проверка качества данных;
- `/api/reports/lessons.csv` - CSV-отчёт;
- `/api/audit` - журнал аудита;
- `/health` - проверка работоспособности сервера и соединения с базой.

### База данных

Используется PostgreSQL

Основные сущности:

- `users`, `refresh_tokens` - пользователи и токены обновления сессии;
- `groups`, `students` - учебные группы и студенты;
- `disciplines`, `discipline_groups` - дисциплины и связи с группами;
- `schedule_entries` - занятия в расписании, привязанные к конкретной дате;
- `bells`, `bell_presets`, `bell_preset_entries`, `bell_weekday_presets` - расписание звонков и пресеты;
- `topics` - планируемые темы занятий;
- `lessons` - проведённые или внесённые в журнал занятия;
- `grades` - оценки студентов;
- `attendance` - посещаемость;
- `semesters` - границы семестров;
- `audit_log` - записи аудита.

Схема создаётся и обновляется при запуске backend посредством SQL-инициализации

### Infrastructure

Корневой файл: `docker-compose.yml`

Инфраструктура состоит из трёх сервисов:

| Сервис     | Назначение                                                  |
| ---------- | ----------------------------------------------------------- |
| `frontend` | Сборка Flutter Web и раздача статических файлов через Nginx |
| `backend`  | Node.js REST API                                            |
| `db`       | PostgreSQL 16 и постоянное хранение данных в Docker volume  |

Nginx раздаёт frontend и проксирует запросы `/api/` к backend. Маршрут `/health` также проксируется к API. Это позволяет использовать интерфейс и API через один внешний адрес без отдельной настройки API URL в браузере.

Дополнительные инфраструктурные файлы:

- `frontend/Dockerfile` - многоэтапная сборка Flutter Web и запуск Nginx;
- `frontend/nginx.conf` - раздача приложения и проксирование API;
- `backend/Dockerfile` - образ Node.js для API;
- Docker volume `journal_db` - сохранение данных PostgreSQL между перезапусками контейнеров;
- внутренняя сеть `journal_net` - связь сервисов Compose.
