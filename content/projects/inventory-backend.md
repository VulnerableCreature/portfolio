Backend-приложение для учёта имущества, сотрудников, помещений и операций выдачи. Проект построен на Laravel и предоставляет версионированный REST API для управления основными сущностями системы.

## Описание приложения

Приложение предназначено для централизованного учёта имущества организации и связанных с ним операций. Оно хранит сведения об активах, сотрудниках, помещениях, пользователях и выдачах, а также поддерживает кошельки и транзакции в рамках реализованной доменной модели.

Основные предметные области:

- **Имущество (Assets):** создание, просмотр, изменение, удаление, управление количеством и статусом; предусмотрены проверки инвентарных номеров и допустимого количества.
- **Сотрудники (Employees):** ведение списка сотрудников и карточек сотрудников.
- **Помещения (Rooms):** управление помещениями и назначение/снятие жильцов или закреплённых occupants.
- **Выдачи (Issuances):** регистрация выдачи имущества или устройств, указание количества, помещения, даты, комментария и связанных параметров.
- **Пользователи и профиль:** вход и выход, управление пользователями и данными профиля.
- **Кошельки и транзакции:** отдельные модели, обработчики и API-операции для кошельков и транзакций.

Фактический состав доступных операций определяется маршрутами в `routes/api.php` и `routes/groups/`.

## Основное назначение

Основная цель проекта - предоставить единый API для учёта материальных активов и связанных процессов. Он позволяет:

1. Хранить каталог имущества и отслеживать его состояние и количество.
2. Вести сведения о сотрудниках и помещениях.
3. Фиксировать выдачу имущества, её параметры и комментарии.
4. Управлять учётными записями и профилями пользователей.
5. Разделять операции чтения и изменения на уровне прикладной архитектуры.
6. Возвращать клиенту структурированные ответы API через Laravel Resources и Collections.

Проект является backend-основой: пользовательский интерфейс для всех перечисленных сценариев в данном архиве не представлен как отдельное приложение.

## Архитектура и составляющие

### Backend

Backend реализован на PHP и Laravel. HTTP API имеет префикс `/api/v1` и использует контроллеры, классы запросов для валидации, ресурсы для сериализации ответов и отдельные прикладные обработчики.

Ключевые каталоги:

| Каталог                 | Назначение                                                                         |
| ----------------------- | ---------------------------------------------------------------------------------- |
| `app/Http/Controllers/` | HTTP-контроллеры, связывающие запросы с прикладными операциями                     |
| `app/Http/Requests/`    | Валидация входных данных                                                           |
| `app/Http/Resources/`   | Формирование API-ответов и коллекций                                               |
| `app/Application/`      | Команды и запросы прикладного уровня                                               |
| `app/Module/`           | Обработчики команд/запросов, DTO, фильтры, перечисления, исключения и оркестраторы |
| `app/CQRS/`             | Интерфейсы и реализация Command Bus / Query Bus                                    |
| `app/Models/`           | Eloquent-модели предметных сущностей                                               |
| `routes/api.php`        | Основные API-маршруты                                                              |
| `routes/groups/`        | Маршруты, сгруппированные по доменам                                               |
| `database/migrations/`  | Миграции схемы базы данных                                                         |
| `database/seeders/`     | Начальное заполнение данных                                                        |

#### CQRS

В проекте применяется подход CQRS: операции изменения представлены командами (`Command`), операции чтения — запросами (`Query`). Они передаются соответствующим обработчикам через Command Bus и Query Bus. Для некоторых сценариев также предусмотрены оркестраторы, объединяющие несколько операций.

Это разделение помогает изолировать HTTP-слой от бизнес-логики и организовать обработку предметных сценариев по отдельным модулям.

#### Основные API-маршруты

Все перечисленные ниже маршруты находятся под `/api/v1`. За исключением входа, маршруты защищены middleware `auth:sanctum` и ограничением частоты запросов `throttle:api`.

| Раздел                         | Доступные операции по маршрутам                                                                               |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| Авторизация                    | `POST /login`, `DELETE /logout`                                                                               |
| Профиль                        | `GET /profile`, `PATCH /profile`                                                                              |
| Пользователи                   | `GET /users`, `GET /users/{id}`, `POST /users`, `DELETE /users/{id}`                                          |
| Имущество                      | `GET /assets`, `GET /assets/{id}`, `POST /assets`, `PATCH /assets/{id}`, `DELETE /assets/{id}`                |
| Сотрудники                     | `GET /employees`, `GET /employees/{id}`, `POST /employees`, `PATCH /employees/{id}`, `DELETE /employees/{id}` |
| Помещения                      | `GET /rooms`, `GET /rooms/{id}`, `POST /rooms`, `PATCH /rooms/{id}`, `DELETE /rooms/{id}`                     |
| occupants помещений            | `POST /rooms/occupants/{id}`, `DELETE /rooms/occupants/{id}`                                                  |
| Выдачи                         | REST-набор маршрутов ресурса `/issuances`                                                                     |
| Кошелёк                        | `GET /wallets/{id}`                                                                                           |
| Привязка кошелька пользователю | `POST /users/wallets/{id}`                                                                                    |

Для точных форматов запросов, параметров фильтрации и структуры ответов следует обращаться к соответствующим `FormRequest`, контроллерам и `JsonResource` в `app/Http/`.

| **Laravel Sanctum 4**                  | Аутентификация API                                                                              |

| **CQRS**                               | Разделение команд изменения и запросов чтения                                                   |

| **Axios**                              | HTTP-клиент для JavaScript                                                                      |

```text
.
├── app/
```
