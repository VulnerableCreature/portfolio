Веб-приложение для подключения организации из Яндекс.Карт, сбора её отзывов и просмотра результатов в личном интерфейсе. Проект состоит из backend API на Laravel и frontend SPA на Vue 3. Сбор отзывов выполняется в фоновой очереди, а данные сохраняются в MySQL.

## Возможности

- Авторизация пользователя через email и пароль с использованием Laravel Sanctum и cookie-based SPA-аутентификации.
- Подключение организации по ссылке на карточку Яндекс.Карт.
- Проверка и нормализация URL организации; поддержка коротких ссылок с разрешением HTTP-редиректа.
- Получение названия организации, рейтинга, количества оценок и общего количества отзывов, если эти данные доступны в ответе источника.
- Фоновый сбор отзывов с отображением статуса процесса в интерфейсе.
- Сохранение автора, оценки, текста и даты публикации отзыва.
- Постраничный просмотр отзывов — по 50 записей на страницу.
- Повторный запуск сбора отзывов для подключённой организации.
- Обновление существующих записей без создания дубликатов при повторном сборе.
- Хранение истории запусков парсинга и снимков агрегированных показателей организации.
- Docker Compose-конфигурация для локального запуска и отдельная конфигурация для production-развёртывания.

## Цель и задачи проекта

### Цель

Разработать веб-приложение, позволяющее пользователю подключить организацию из Яндекс.Карт, получить доступные отзывы и просматривать их в едином интерфейсе без необходимости вручную открывать карточку организации и листать отзывы на сайте.

### Задачи

1. Реализовать авторизацию и ограничить доступ к данным подключённой организации авторизованным пользователем.
2. Принимать ссылки на карточки организаций, проверять их корректность и приводить к нормализованному виду.
3. Получать сведения об организации и отзывы из доступных ответов Яндекс.Карт.
4. Перенести сбор отзывов в фоновые задачи, чтобы длительные сетевые операции не блокировали HTTP-запрос пользователя.
5. Хранить сведения об организации, отзывах, запусках парсинга и результатах отдельных запусков в базе данных.
6. Обеспечить повторный сбор без дублирования уже сохранённых отзывов.
7. Предоставить интерфейс для просмотра статуса организации, статистики и списка отзывов с пагинацией.
8. Контролировать ошибки сбора и предусмотреть повторные попытки при сбоях.
9. Упростить локальный запуск и развёртывание за счёт контейнеризации.

## Способы достижения цели

- **Разделение frontend и backend.** Vue SPA отвечает за пользовательский интерфейс, а Laravel предоставляет JSON API и выполняет бизнес-операции.
- **Cookie-based авторизация.** Laravel Sanctum используется для аутентификации SPA. Перед входом frontend запрашивает CSRF-cookie.
- **Валидация ссылок.** URL проверяется по допустимым доменам Яндекс.Карт. Короткие ссылки разрешаются через HTTP-редирект, после чего определяется идентификатор организации.
- **Фоновая обработка.** После подключения организации создаётся запись о запуске парсинга и отправляется `ParseOrganizationReviewsJob`. В production очередь обрабатывается отдельным контейнером `queue-worker`.
- **Ограничение нагрузки на источник.** Между запросами страниц отзывов применяется настраиваемая задержка со случайным отклонением; User-Agent выбирается из заданного списка.
- **Устойчивость к сетевым ошибкам.** Для фоновой задачи заданы повторные попытки и увеличивающиеся интервалы ожидания.
- **Идемпотентное сохранение.** Для отзыва рассчитывается SHA-256-хеш содержимого. Репозиторий обновляет существующую запись или создаёт новую по внешнему идентификатору.
- **Разделение ответственности в backend.** Контроллеры принимают HTTP-запросы, application services координируют сценарии, репозитории отвечают за работу с данными, а сервис парсинга взаимодействует с Яндекс.Картами.
- **Контейнеризация.** Docker Compose объединяет frontend, backend, Nginx, MySQL и Redis.

### Backend

Backend находится в каталоге `backend/` и использует Laravel.

- `app/Http/Controllers/Api/` — HTTP-контроллеры авторизации, организации и отзывов.
- `app/Http/Requests/` — валидация входных запросов.
- `app/Http/Resources/` — преобразование моделей в JSON-ответы.
- `app/Application/` — сценарии приложения: авторизация, подключение организации, повторный запуск парсинга и получение отзывов.
- `app/Application/*/Contracts/` — интерфейсы application-сервисов.
- `app/Repositories/` — чтение и запись организаций, отзывов, запусков парсинга и снимков.
- `app/Repositories/Contracts/` — контракты репозиториев.
- `app/Services/YandexMaps/` — проверка и разрешение URL, HTTP-взаимодействие с Яндекс.Картами, преобразование полученных данных в DTO.
- `app/Services/YandexMaps/DTO/` — объекты данных организации и отзыва.
- `app/Jobs/ParseOrganizationReviewsJob.php` — фоновая задача сбора отзывов.
- `app/Models/` — Eloquent-модели.
- `database/migrations/` — схема базы данных.
- `database/seeders/` — начальные данные для локальной разработки.

`RepositoryServiceProvider` связывает интерфейсы с реализациями через контейнер зависимостей Laravel.

### Frontend

Frontend находится в каталоге `frontend/` и представляет собой SPA на Vue 3.

- `src/main.js` — создание Vue-приложения и подключение Pinia, Vue Router и глобальных стилей.
- `src/App.vue` — общий каркас приложения, навигация и выход из системы.
- `src/router/index.js` — маршруты входа, отзывов и настроек, а также проверка авторизации перед переходом.
- `src/api/http.js` — экземпляры Axios и запрос CSRF-cookie.
- `src/stores/auth.js` — состояние пользователя, вход, выход и проверка текущей сессии.
- `src/stores/organization.js` — загрузка организации, запуск повторного парсинга, получение отзывов и опрос статуса.
- `src/views/` — страницы входа, отзывов и настроек организации.
- `src/components/` — карточка отзыва и компонент пагинации.

Во время парсинга frontend повторно запрашивает состояние организации примерно раз в 3 секунды. Когда парсинг завершается, список отзывов загружается заново.

## Как работает сбор отзывов

1. Пользователь входит в систему.
2. На странице настроек вводит ссылку на организацию в Яндекс.Картах.
3. Backend проверяет URL. Для короткой ссылки сначала определяется конечный адрес после редиректа.
4. Приложение извлекает идентификатор организации и сохраняет нормализованный адрес.
5. Создаётся запись `parsing_jobs` со статусом `queued`, а в очередь отправляется `ParseOrganizationReviewsJob`.
6. Worker запускает application service, который вызывает `YandexMapsParserService`.
7. Парсер получает сведения о карточке организации и открывает сессию для получения отзывов. Для запросов отзывов используются внутренние запросы Яндекс.Карт, включая `fetchReviews`.
8. Отзывы запрашиваются страницами по 50 записей. Текущая реализация ограничивает сбор максимум 600 отзывами за запуск.
9. В ходе сбора обновляется прогресс задачи: количество полученных отзывов и оценка общего количества, если источник её возвращает.
10. Репозиторий создаёт новые отзывы или обновляет существующие. Для определения изменения содержимого используется хеш автора, оценки, текста и даты.
11. После успешного завершения обновляются агрегированные данные организации и создаётся снимок результатов запуска.
12. Frontend отображает статус и после завершения загружает список отзывов.

Для фоновой задачи настроены до трёх попыток выполнения и интервалы повторов `[30, 120, 300]` секунд. Фактическое поведение очереди зависит от конфигурации подключения и запуска worker.

## Модель данных

### `users`

Пользователи приложения. Авторизация выполняется по email и паролю.

### `organizations`

Подключённые организации:

- пользователь-владелец;
- исходная и нормализованная ссылки;
- идентификатор организации в Яндекс.Картах;
- название, рейтинг, количество оценок и отзывов;
- статус и текст ошибки парсинга;
- дата последнего успешного сбора.

### `reviews`

Сохранённые отзывы:

- организация;
- внешний идентификатор отзыва;
- автор;
- оценка;
- текст;
- дата публикации;
- хеш содержимого для обнаружения изменений.

### `parsing_jobs`

История запусков сбора:

- организация и статус задачи;
- количество полученных отзывов;
- оценка общего количества отзывов;
- номер попытки;
- сообщение об ошибке;
- время начала и завершения.

### `review_snapshots`

Снимки агрегированных показателей организации, связанные с конкретным запуском парсинга. Хранят рейтинг, количество оценок и отзывов, а также поля для количества добавленных, изменённых и удалённых отзывов. В текущей реализации подсчитываются добавленные и изменённые отзывы; полноценное обнаружение удалённых отзывов не реализовано.

## API

API расположен в backend и использует префикс `/api`. Все перечисленные маршруты, кроме `POST /api/login`, требуют аутентификации через Sanctum.

| Метод  | Endpoint                    | Назначение                                       |
| ------ | --------------------------- | ------------------------------------------------ |
| `POST` | `/api/login`                | Вход по email и паролю                           |
| `POST` | `/api/logout`               | Выход из системы                                 |
| `GET`  | `/api/me`                   | Получение текущего пользователя                  |
| `GET`  | `/api/organization`         | Получение подключённой организации и её статуса  |
| `POST` | `/api/organization`         | Подключение организации по URL и запуск парсинга |
| `POST` | `/api/organization/reparse` | Повторный запуск парсинга                        |
| `GET`  | `/api/reviews?page=1`       | Получение страницы отзывов                       |

`GET /api/reviews` возвращает список отзывов в `data` и информацию о пагинации в `meta`: текущая страница, последняя страница, размер страницы и общее количество записей. Размер страницы на backend — 50 отзывов.

Для cookie-based SPA-аутентификации перед входом необходимо получить CSRF-cookie через `/sanctum/csrf-cookie`. Frontend должен отправлять credentials/cookies и обращаться к этому маршруту через доступный ему origin или настроенный proxy.

## Ограничения

- Парсер использует внутренние, не документированные как публичный контракт запросы Яндекс.Карт. Яндекс может изменить формат ответа или механизм получения отзывов; в таком случае парсер может потребовать обновления.
- За один запуск собирается не более 600 отзывов. Это ограничение задано в `YandexMapsParserService`.
- Сбор зависит от доступности Яндекс.Карт, сетевых ограничений и ответов источника.
- В проекте предусмотрен отдельный статус `markup_changed` для ситуации, когда ожидаемая структура ответа источника изменилась.
- Повторный сбор обновляет существующие отзывы по внешнему идентификатору и хешу содержимого.
- Таблица `review_snapshots` содержит поле `reviews_removed`, но актуальная реализация репозитория не определяет удалённые отзывы и обычно сохраняет для этого показателя `0`.
